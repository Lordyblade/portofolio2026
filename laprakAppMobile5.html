Arsitektur Navigasi: Named Routes & Bottom Navigation Bar

Ibrahim Mousa Dhani 2411532010
IF - Universitas Andalas

A. Pendahuluan

Named Routes
Named Routes adalah metode navigasi Flutter yang menggunakan nama berupa string untuk mengakses halaman. Nama rute didaftarkan pada properti routes di MaterialApp, sehingga pemanggilan halaman tidak perlu menuliskan MaterialPageRoute berulang kali di setiap tombol. Pada praktikum ini, rute “/” digunakan untuk halaman utama yang memiliki tab, sedangkan rute “/add” digunakan untuk halaman tambah transaksi.

Properti initialRoute menentukan halaman pertama yang dibuka. Sementara itu, routes berisi pemetaan nama rute dengan widget yang akan ditampilkan. Setelah rute didaftarkan, perpindahan dapat dilakukan dengan Navigator.pushNamed(context, “/add”).

Bottom Navigation Bar
BottomNavigationBar merupakan menu navigasi yang diletakkan di bagian bawah layar. Menu ini dapat digunakan untuk berpindah antara halaman utama seperti Beranda, Riwayat, dan Profil tanpa harus membangun navigasi baru pada setiap halaman.

Properti currentIndex menunjukkan tab yang sedang aktif, sedangkan items berisi ikon dan label tiap tab. Ketika pengguna memilih tab, fungsi onTap menerima indeks pilihan. Nilai indeks kemudian diubah menggunakan setState() agar Flutter membangun ulang tampilan dengan halaman yang sesuai.

B. Tujuan Praktikum

Adapun tujuan dari pelaksanaan praktikum ini adalah sebagai berikut:

  • Menerapkan Named Routes untuk navigasi terpusat dan rapi.
  • Membangun menu bawah (BottomNavigationBar) ala aplikasi modern.
  • Mengintegrasikan Dashboard, Riwayat, dan Profil dalam satu wadah.

C. Alat

Perangkat dan dependensi yang digunakan selama praktikum:

  • Flutter SDK
  • Code Editor : VS Code atau Android Studio.
  • Emulator / Device

D. Langkah-langkah Praktikum

Praktikum 5 ini merupakan lanjutan dari proyek Flutter pada Praktikum 4 sebelumnya. Buka proyek sebelumnya, kemudian pastikan file main.dart, dashboard_screen.dart, add_transaction_screen.dart, dan transaction_detail_screen.dart masih tersedia di dalam folder lib. File baru main_screen.dart dibuat untuk menampung tab utama aplikasi. File profile_screen.dart juga diperlukan karena diimpor oleh MainScreen dan akan diselesaikan pada bagian latihan.

1. Mendaftarkan Named Routes pada main.dart

Pada file main.dart, pemanggilan halaman awal melalui properti home diganti dengan initialRoute dan routes. Dengan cara ini, halaman utama diakses melalui rute “/”, sedangkan halaman tambah transaksi diakses melalui rute “/add”.

Bagian initialRoute: “/” menetapkan MainScreen sebagai halaman pertama. Pemetaan di dalam routes menghubungkan setiap nama rute dengan widget tujuan. Baris yang mengarah ke AddTransactionScreen memungkinkan layar input transaksi dibuka melalui nama rute, bukan dengan membuat MaterialPageRoute secara langsung.

2. Membuat MainScreen sebagai Penampung Tab

Buat file main_screen.dart. Widget MainScreen menggunakan StatefulWidget karena indeks tab aktif dapat berubah ketika pengguna memilih menu yang berbeda. Variabel _selectedIndex dimulai dari 0 sehingga tab Beranda aktif ketika halaman pertama kali dibuka.

List _pages menampung widget yang ditampilkan. Dalam versi dasar modul, halaman Dashboard diambil dari Praktikum IV, halaman Riwayat masih berupa teks sementara, dan halaman Profil mengarah ke ProfileScreen. Setelah pengguna memilih menu, fungsi _onItemTapped() memanggil setState() untuk memperbarui _selectedIndex. Bagian body kemudian menampilkan widget sesuai indeks yang aktif.

BottomNavigationBar memiliki tiga item, yaitu Beranda, Riwayat, dan Profil. Nilai currentIndex mengikuti _selectedIndex, sementara onTap menjalankan _onItemTapped. Dengan susunan ini, navigasi antartab dikelola dari satu Scaffold utama.

3. Memperbarui Tombol Tambah pada Dashboard

Buka dashboard_screen.dart yang sudah dibuat pada Praktikum IV. Pada bagian floatingActionButton, ganti navigasi berbasis Navigator.push dan MaterialPageRoute dengan Navigator.pushNamed. Rute “/add” sudah terdaftar pada main.dart sehingga tombol dapat memanggilnya secara langsung.

Ketika tombol tambah ditekan, Flutter membuka AddTransactionScreen melalui rute “/add”. Setelah pengguna menutup halaman tersebut dengan Navigator.pop(), aplikasi kembali ke halaman sebelumnya, yaitu Dashboard.

Latihan

Pada latihan ini dilakukan pengembangan tiga fitur yang diminta dalam modul, yaitu halaman Riwayat Transaksi, halaman Profil dengan avatar, nama, email, dan tombol logout, serta halaman Login berisi input email dan password. Setelah login, aplikasi membuka halaman utama dan menampilkan email yang dimasukkan pengguna.

Membuat Halaman Riwayat Transaksi

Buat file history_screen.dart. Halaman ini menampilkan beberapa contoh transaksi dalam bentuk daftar. Data masih ditulis langsung pada kode untuk keperluan tampilan, sehingga belum mengambil data secara dinamis dari penyimpanan aplikasi.

List transactions menyimpan contoh judul, nominal, kategori, tanggal, dan jenis transaksi. ListView.builder menampilkan data tersebut satu per satu. Warna hijau digunakan untuk pemasukan, sedangkan warna merah digunakan untuk pengeluaran agar keduanya mudah dibedakan.

Membuat Halaman Profil

Buat atau perbarui file profile_screen.dart. Halaman ini menampilkan avatar, nama pengguna, email, dan tombol Logout. Email diterima melalui constructor dari halaman utama. Agar nama tidak hanya berupa teks tetap, halaman Profil menggunakan getter _displayName untuk membentuk nama tampilan dari bagian alamat email sebelum tanda @. Dengan demikian, isi Profil mengikuti email yang dimasukkan pada halaman Login, tanpa memerlukan kolom nama tambahan.

Getter _displayName mengambil bagian email sebelum tanda @, menghapus angka, mengganti pemisah seperti titik, garis bawah, dan tanda hubung menjadi spasi, lalu mengubah huruf awal setiap kata menjadi kapital. Contohnya, email ibrahim.mousa@gmail.com ditampilkan sebagai “Ibrahim Mousa”. Nama tersebut merupakan nama tampilan yang diperkirakan dari email, bukan nama asli yang diambil dari akun atau database; jika nama asli harus diinput pengguna, formulir Login perlu ditambah kolom Nama. Tombol Logout menggunakan Navigator.pushNamedAndRemoveUntil untuk kembali ke halaman Login sekaligus menghapus rute sebelumnya dari tumpukan navigasi, sehingga pengguna tidak langsung kembali ke halaman utama menggunakan tombol kembali setelah logout.

Membuat Halaman Login

Buat file login_screen.dart. Form Login memiliki TextFormField untuk email dan password. Validasi memastikan email tidak kosong dan memiliki karakter “@”, serta password wajib diisi. Karena tugas berfokus pada navigasi dan pengiriman data, login ini hanya berupa simulasi antarmuka dan belum melakukan pemeriksaan akun melalui server atau database.

Ketika tombol Login ditekan, fungsi _login() memeriksa validitas form. Jika valid, email yang telah di-trim dikirim melalui argumen pada Navigator.pushReplacementNamed(context, "/", arguments: email). Rute halaman Login digantikan oleh halaman utama sehingga pengguna berpindah ke aplikasi tanpa menumpuk halaman Login di atasnya.

Mengintegrasikan Rute Login

Agar aplikasi latihan dimulai dari Login, ubah main.dart. Versi dasar pada langkah praktikum menggunakan initialRoute “/”, sedangkan versi latihan menggunakan initialRoute “login” tanpa garis miring awal. Penamaan ini menghindari perilaku Flutter yang dapat membentuk rute “/” sebagai rute perantara saat menyusun initial route. Rute “/” tetap mengarah ke MainScreen dan rute “/add” tetap mengarah ke AddTransactionScreen.

Perubahan initialRoute tersebut diperlukan hanya untuk memenuhi alur Login pada tugas. Pada tahap dasar Named Routes, initialRoute “/” tetap sesuai dengan urutan yang diberikan dalam modul. Nama rute “login” tanpa garis miring awal digunakan khusus pada versi latihan agar layar Login dibuka sebagai satu rute awal.

Memperbarui MainScreen untuk Menampilkan Email dan Halaman Riwayat

Perbarui file main_screen.dart agar daftar halaman menggunakan HistoryScreen yang sudah dibuat. MainScreen membaca email dari argumen rute melalui ModalRoute.of(context)?.settings.arguments. Email tersebut diteruskan ke DashboardScreen dan ProfileScreen. Pada Dashboard, nama tampilan dibuat dari bagian email sebelum tanda @, sedangkan alamat email lengkap tetap ditampilkan di bawah sapaan.

Pada versi akhir ini, Dashboard menerima email dari halaman Login melalui argumen named route. Getter _displayName membentuk nama tampilan dari bagian email sebelum tanda @ dengan mengganti pemisah titik, garis bawah, atau tanda hubung menjadi spasi, menghapus angka, dan mengubah huruf awal setiap kata menjadi kapital. Contohnya, ibrahim.mousa@gmail.com akan menghasilkan sapaan “Halo, Ibrahim Mousa”. Alamat email lengkap juga ditampilkan pada baris tersendiri di bawah sapaan. Tampilan saldo, daftar transaksi, dan tombol tambah tetap dipertahankan dari Dashboard Praktikum IV; tombol tambah menggunakan named route “/add” sesuai Modul V.

Variabel displayedEmail memastikan alamat email dari Login ditampilkan apa adanya setelah spasi di awal atau akhir dihilangkan. Sementara itu, $_displayName merujuk pada getter yang mengubah bagian nama sebelum tanda @ menjadi nama tampilan yang lebih mudah dibaca. Nama tersebut hanya perkiraan berdasarkan teks email dan bukan nama asli yang diverifikasi. Dua informasi ini membuat hasil latihan sesuai instruksi modul: setelah tombol Login ditekan, halaman utama terbuka dan menampilkan informasi email yang dimasukkan pengguna.

Outputnya

Setelah halaman Riwayat dikembangkan, halaman ini digunakan untuk menampilkan informasi transaksi yang telah dilakukan pengguna. Pengujian dilakukan dengan memilih menu Riwayat pada Bottom Navigation Bar untuk memastikan halaman dapat dibuka dan menampilkan informasi transaksi sesuai dengan implementasi yang dibuat.

Selanjutnya, halaman Profil dikembangkan untuk menampilkan informasi pengguna, seperti avatar, nama pengguna, dan alamat email, serta menyediakan tombol Logout. Pengujian dilakukan untuk memastikan informasi pengguna dapat ditampilkan dengan baik dan halaman Profil dapat diakses melalui Bottom Navigation Bar.

Berikutnya, halaman Login dibuat dengan menyediakan kolom email, kata sandi, dan tombol Login. Pengguna memasukkan email dan kata sandi pada kolom yang tersedia, kemudian menekan tombol Login untuk masuk ke halaman utama aplikasi.

Setelah tombol Login ditekan, aplikasi berpindah ke halaman utama dan menampilkan email yang telah dimasukkan oleh pengguna. Pengujian ini dilakukan untuk memastikan navigasi dari halaman Login ke halaman utama berjalan dengan baik serta informasi email dapat diteruskan dan ditampilkan sesuai dengan input pengguna.

E. Kesimpulan

Berdasarkan praktikum yang telah dilakukan, dapat disimpulkan bahwa navigasi merupakan bagian penting dalam pengembangan aplikasi Flutter karena memungkinkan pengguna berpindah dari satu halaman ke halaman lainnya dengan mudah. Melalui praktikum ini, penggunaan Named Routes dipelajari untuk mengatur navigasi berdasarkan nama rute, sedangkan Bottom Navigation Bar digunakan untuk mempermudah perpindahan antara halaman Beranda, Riwayat, dan Profil. Selain itu, praktikum ini merupakan pengembangan dari Modul IV dengan mempertahankan fitur utama Dashboard dan penambahan transaksi, sekaligus mengintegrasikan beberapa halaman agar aplikasi menjadi lebih terstruktur.

Melalui latihan yang dikerjakan, pemahaman mengenai pengiriman data ant halaman juga bertambah, terutama dalam meneruskan email yang dimasukkan pada halaman Login ke halaman utama aplikasi. Informasi tersebut dapat ditampilkan pada Dashboard maupun Profil sesuai kebutuhan, sehingga halaman dapat menampilkan data berdasarkan masukan pengguna. Dengan demikian, praktikum ini memberikan pemahaman mengenai penerapan navigasi, pengelolaan perpindahan halaman, dan pengiriman data dalam Flutter sebagai dasar untuk mengembangkan aplikasi yang lebih kompleks.
