Laporan Praktikum 6 - Aplikasi Mobile

State Management pada Aplikasi ResepKu

Ibrahim Mousa Dhani 2411532010
IF - Universitas Andalas

A. Pendahuluan

State management merupakan cara untuk mengelola data yang dapat berubah selama aplikasi berjalan dan memengaruhi tampilan antarmuka. Pada pengembangan aplikasi Flutter, pengelolaan state dapat dilakukan menggunakan setState() maupun Provider. setState() digunakan untuk data lokal yang hanya dibutuhkan oleh satu widget atau halaman, sedangkan Provider lebih sesuai untuk data yang perlu dibagikan dan diakses oleh beberapa widget atau halaman sekaligus.

Pada praktikum ini dikembangkan aplikasi ResepKu dengan fitur pengaturan jumlah porsi dan daftar resep favorit. Fitur jumlah porsi menggunakan setState() karena hanya diperlukan pada halaman detail resep. Sementara itu, fitur favorit menggunakan Provider melalui ChangeNotifier, sehingga status favorit dapat dibaca dan diperbarui dari daftar resep, halaman detail, badge pada AppBar, dan halaman Favorit. Praktikum juga mencakup penerapan tema gelap dan terang serta fitur untuk menghapus seluruh resep favorit dengan konfirmasi pengguna.

B. Tujuan Praktikum

Setelah menyelesaikan modul ini, mahasiswa mampu:

  • Membuat state lokal dengan StatefulWidget dan setState() pada fitur jumlah porsi di halaman detail.
  • Menjelaskan keterbatasan state lokal ketika satu data dibutuhkan oleh banyak widget dan halaman.
  • Membuat state global dengan package provider (ChangeNotifier dan MultiProvider) pada fitur favorit.
  • Membaca state dengan context.watch, context.read, dan Consumer di beberapa halaman.

C. Alat

Perangkat dan dependensi yang digunakan selama praktikum:

  • Flutter SDK
  • Code Editor : VS Code atau Android Studio.
  • Emulator Android, atau HP Android dengan USB debugging aktif.
  • Koneksi internet untuk menjalankan flutter pub add.

D. Langkah-langkah Praktikum

Bagian A — Menyiapkan ResepKu dan State Lokal

Bertujuan membuat project ResepKu dengan halaman Home dan Detail, serta fitur jumlah porsi yang memakai setState().

1. Menyiapkan project ResepKu

Project dibuat menggunakan perintah flutter create resepku, kemudian folder lib disusun menjadi models, data, providers, pages, dan widgets. Model Recipe dibuat untuk merepresentasikan data resep, seperti nama, jenis masakan, tingkat kesulitan, waktu memasak, jumlah porsi, kalori, rating, gambar, dan bahan-bahan. Selanjutnya, enam data resep awal dimasukkan ke dalam dummy_recipes.dart sebagai sumber data sementara.

2. Membuat halaman Home dan Detail

Halaman HomePage menampilkan daftar resep dari dummyRecipes menggunakan widget RecipeTile. Setiap resep dapat dipilih untuk membuka DetailPage. Halaman detail menampilkan informasi resep, daftar bahan, jumlah porsi, dan total kalori. Pada tahap ini juga dibuat IdentityFooter dan dipasang melalui parameter builder pada MaterialApp agar identitas mahasiswa tampil di bagian bawah setiap halaman.

3. Menerapkan state lokal dengan setState()

DetailPage dibuat sebagai StatefulWidget karena jumlah porsi dapat berubah ketika tombol tambah atau kurang ditekan. Nilai awal porsi diambil dari widget.recipe.servings melalui initState(). Perubahan jumlah porsi dilakukan menggunakan setState(), kemudian total kalori dihitung berdasarkan perkalian kalori per porsi dengan jumlah porsi yang sedang dipilih. Tombol kurang dibuat tidak aktif ketika jumlah porsi sudah mencapai satu.

Checkpoint 1

Checkpoint 1 dilakukan dengan membuka detail Classic Margherita Pizza dan mengubah jumlah porsi menjadi 6. Dengan kalori sebesar 300 kkal per porsi, total kalori yang ditampilkan harus menjadi 1.800 kkal. Tombol kurang dibuat nonaktif ketika porsi bernilai 1 melalui kondisi onPressed: _servings > 1 ? _removeServing : null.

Bagian B — Eksperimen: Favorit dengan State Lokal

Bertujuan melihat secara langsung keterbatasan state lokal ketika satu data dibutuhkan di banyak tempat. Sebelum memakai Provider, kita coba cara yang paling sederhana terlebih dahulu: setiap RecipeTile menyimpan status favoritnya sendiri dengan setState().

1. Mengganti RecipeTile

Ganti seluruh isi recipe_tile.dart dengan versi eksperimen berikut.

RecipeTile diubah menjadi StatefulWidget dan setiap tile diberi variabel _isFavorite bertipe boolean. Ikon hati berubah ketika ditekan karena nilai variabel tersebut diperbarui menggunakan setState(). Namun, status favorit hanya tersimpan pada masing-masing RecipeTile sehingga HomePage maupun DetailPage tidak dapat membaca status tersebut secara langsung. Eksperimen ini menunjukkan bahwa state lokal kurang sesuai untuk data yang perlu digunakan bersama oleh beberapa bagian aplikasi.

Bagian C — Fitur Favorit dengan Provider

Bertujuan menyimpan daftar favorit sebagai app state, lalu membacanya dari daftar resep, halaman detail, badge, dan halaman Favorit.

1. Menerapkan Provider untuk fitur favorit

Package Provider dipasang menggunakan perintah flutter pub add provider. Selanjutnya dibuat FavoriteProvider yang meng-extend ChangeNotifier dan menyimpan daftar resep pada variabel _items. Method toggle() digunakan untuk menambahkan atau menghapus resep dari daftar favorit, sedangkan method clear() digunakan untuk mengosongkan seluruh daftar. Setiap perubahan diikuti pemanggilan notifyListeners() agar widget yang mendengarkan perubahan dapat memperbarui tampilannya.

FavoriteProvider didaftarkan melalui MultiProvider di atas MaterialApp agar dapat diakses oleh semua halaman. RecipeTile, DetailPage, FavoriteBadgeButton, dan FavoritePage kemudian dihubungkan dengan Provider. context.watch digunakan ketika widget perlu memperbarui tampilan saat data berubah, sedangkan context.read digunakan ketika hanya perlu memanggil method, misalnya ketika ikon hati ditekan. Halaman Favorit menggunakan Consumer untuk menampilkan daftar resep yang disimpan.

Pengamatan Bagian B

1. Apakah ikon hati berubah? Mengapa?
Ikon hati berubah ketika ditekan, karena setiap RecipeTile memiliki variabel _isFavorite yang menyimpan status favoritnya sendiri. Ketika ikon ditekan, nilai variabel tersebut dibalik menggunakan setState(), sehingga widget membangun ulang tampilannya dan menampilkan ikon hati terisi atau kosong sesuai nilai terbaru.

2. Apakah jumlah resep favorit dapat ditampilkan pada AppBar HomePage? Di class mana data _isFavorite berada dan apakah HomePage dapat membacanya?
Jumlah resep favorit tidak dapat diketahui secara langsung oleh HomePage pada eksperimen ini. Variabel _isFavorite berada di dalam class _RecipeTileState, sehingga setiap tile hanya mengetahui status favorit miliknya sendiri. HomePage tidak dapat mengakses variabel tersebut secara langsung karena berada di luar class dan state masing-masing RecipeTile. Oleh sebab itu, diperlukan pengelolaan state bersama seperti Provider agar jumlah favorit dapat dihitung dan ditampilkan pada AppBar.

3. Bagaimana halaman Detail mengetahui bahwa resep sudah difavoritkan?
Status favorit perlu dipindahkan ke state global menggunakan Provider agar dapat diakses oleh halaman daftar, detail, dan halaman Favorit.

2. Mengapa jumlah porsi tetap menggunakan setState() dan tidak dimasukkan ke Provider? Hubungkan dengan hasil skenario 6 pada Langkah C.7.
Jumlah porsi tetap menggunakan setState() karena data tersebut hanya dibutuhkan pada halaman Detail dan tidak perlu dibagikan ke halaman lain. Penggunaan state lokal lebih sederhana dan sesuai untuk perubahan sementara pada satu halaman. Hal ini terlihat pada skenario 6 Langkah C.7, yaitu ketika jumlah porsi diubah menjadi 2 lalu pengguna kembali ke Home dan membuka resep yang sama, jumlah porsi kembali ke nilai awal. Kondisi tersebut terjadi karena state lokal pada halaman Detail dibuang ketika halaman ditutup, sehingga nilai sebelumnya tidak disimpan sebagai state global.

3. Apa yang terjadi jika ChangeNotifierProvider dipindahkan dari main() ke dalam HomePage dan mengapa?
Jika ChangeNotifierProvider dipindahkan ke dalam HomePage dan hanya membungkus Scaffold, halaman Favorit dapat mengalami ProviderNotFoundException ketika dibuka. Hal ini terjadi karena Provider hanya tersedia bagi widget yang berada di bawahnya dalam widget tree. Saat navigasi dilakukan, halaman Favorit dibuat sebagai route baru oleh Navigator yang posisinya berada di atas Provider tersebut, sehingga halaman Favorit bukan bagian dari subtree yang dapat mengakses FavoriteProvider. Oleh karena itu, Provider perlu diletakkan di atas MaterialApp agar dapat diakses oleh seluruh halaman.

Latihan 1 — Tema Gelap dan Terang

Menambahkan halaman Pengaturan yang berisi SwitchListTile "Mode gelap". Ketika switch diaktifkan, seluruh aplikasi berubah ke tema gelap. Ketika switch dinonaktifkan, aplikasi kembali menggunakan tema terang. Pengaturan tema disimpan pada ThemeProvider yang meng-extend ChangeNotifier.

Membuat file lib/providers/theme_provider.dart

Variabel _themeMode menyimpan tema yang sedang digunakan dan pada awalnya diatur ke ThemeMode.light. Getter themeMode digunakan untuk membaca nilai tema. Method setThemeMode() menerima nilai boolean dari switch, kemudian mengubah tema menjadi ThemeMode.dark atau ThemeMode.light. Pemanggilan notifyListeners() memberi tahu widget yang menggunakan provider bahwa nilai tema telah berubah.

Mendaftarkan ThemeProvider dan mengatur MaterialApp pada lib/main.dart

FavoriteProvider tetap didaftarkan agar pengelolaan daftar favorit tidak terganggu. ThemeProvider ditambahkan ke dalam MultiProvider sehingga seluruh halaman dapat mengakses pengaturan tema. Pada ResepKuApp, context.watch().themeMode digunakan untuk membaca tema aktif. Parameter theme mendefinisikan tema terang, darkTheme mendefinisikan tema gelap, dan themeMode menentukan tema yang sedang diterapkan. Footer identitas tetap dipasang melalui builder agar tampil pada setiap halaman.

Membuat halaman lib/pages/settings_page.dart

SettingsPage menggunakan SwitchListTile untuk menampilkan pengaturan mode gelap. Nilai switch dibaca dari themeProvider.themeMode. Ketika switch diubah, context.read() memanggil setThemeMode() dengan nilai terbaru. Dengan demikian, halaman pengaturan tidak perlu mengelola state tema sendiri karena perubahan sudah ditangani oleh ThemeProvider.

Menambahkan tombol Pengaturan pada lib/pages/home_page.dart

Tombol pengaturan ditambahkan pada actions AppBar menggunakan IconButton. Ketika tombol ditekan, Navigator.push() membuka SettingsPage. FavoriteBadgeButton tetap dipertahankan agar badge jumlah favorit masih dapat digunakan bersamaan dengan fitur pengaturan tema.

Output dan Pengujian

Hasil yang diharapkan adalah tema seluruh aplikasi berubah mengikuti posisi switch.

Latihan 2 - Menghapus Semua Favorit

Menambahkan tombol "Hapus semua" berupa ikon, pada appbar halaman favorit yang memanggil clear() dari FavoriteProvider setelah pengguna mengonfirmasi melalui AlertDialog. Tombol harus nonaktif ketika daftar favorit kosong.

Memodifikasi file lib/pages/favorite_page.dart

Consumer FavoriteProvider digunakan agar halaman Favorit menerima data terbaru ketika daftar favorit berubah. Tombol IconButton dengan ikon delete_sweep ditambahkan pada AppBar. Kondisi favorite.count == 0 ? null : ... membuat tombol tidak aktif ketika tidak ada resep favorit. Jika daftar masih berisi data, tombol akan menjalankan showDialog() untuk menampilkan dialog konfirmasi.

Dialog menyediakan dua pilihan. Tombol Batal mengembalikan nilai false, sedangkan tombol Hapus Semua mengembalikan nilai true. Setelah dialog ditutup, program memeriksa nilai confirm. Method clear() pada FavoriteProvider hanya dipanggil ketika pengguna memberikan konfirmasi. Method tersebut mengosongkan daftar favorit dan memanggil notifyListeners(), sehingga Consumer membangun ulang tampilan dan menampilkan pesan bahwa belum ada resep favorit.

Output dan Pengujian

Hasil yang diharapkan adalah seluruh resep favorit hanya terhapus setelah pengguna memilih Hapus Semua pada dialog konfirmasi.

E. Kesimpulan

Berdasarkan praktikum yang telah dilakukan, dapat disimpulkan bahwa state management merupakan bagian penting dalam pengembangan aplikasi Flutter karena berfungsi untuk mengelola perubahan data yang memengaruhi tampilan aplikasi. Melalui praktikum ini, dipelajari penggunaan setState() untuk mengelola state lokal, seperti fitur pengaturan jumlah porsi pada halaman detail resep, serta penggunaan Provider untuk mengelola state global yang membutuhkan akses dari beberapa halaman. Penerapan ChangeNotifier, notifyListeners(), context.watch, context.read, dan Consumer menunjukkan bagaimana data dapat dibagikan dan diperbarui secara terstruktur tanpa harus menyimpan state secara terpisah pada setiap widget. Selain itu, melalui eksperimen pada Bagian B, terlihat bahwa penggunaan state lokal untuk fitur favorit memiliki keterbatasan karena data hanya dapat diakses oleh widget yang menyimpannya. Keterbatasan tersebut dapat diatasi dengan Provider sehingga status favorit dapat digunakan secara konsisten pada halaman Home, Detail, badge AppBar, dan halaman Favorit.
Pada bagian latihan, pengelolaan state juga diterapkan untuk membuat fitur perubahan tema terang dan gelap serta menghapus seluruh resep favorit dengan konfirmasi pengguna. Dengan demikian, praktikum ini memberikan pemahaman mengenai pemilihan dan penerapan state management sesuai kebutuhan aplikasi, sehingga aplikasi menjadi lebih terstruktur, interaktif, dan mudah dikembangkan.
