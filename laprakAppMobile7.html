Laporan Praktikum 7 - Aplikasi Mobile

List, Grid, Gambar, dan Asset pada ResepKu

Ibrahim Mousa Dhani 2411532010
IF - Universitas Andalas

A. Pendahuluan

State management merupakan cara untuk mengelola data yang dapat berubah selama aplikasi berjalan dan memengaruhi tampilan antarmuka. Pada pengembangan aplikasi Flutter, pengelolaan state dapat dilakukan menggunakan setState() maupun Provider. setState() digunakan untuk data lokal yang hanya dibutuhkan oleh satu widget atau halaman, sedangkan Provider lebih sesuai untuk data yang perlu dibagikan dan diakses oleh beberapa widget atau halaman sekaligus.

Pada praktikum ini, aplikasi ResepKu dikembangkan dengan menambahkan pengelolaan tampilan data, gambar, dan asset agar informasi resep dapat disajikan dengan lebih menarik dan mudah digunakan. Materi yang dipraktikkan meliputi penggunaan asset lokal berupa logo dan custom font, penampilan gambar dari internet menggunakan Image.network beserta loading state dan error state, serta penyajian data menggunakan ListView.builder dan GridView.builder. Selain itu, aplikasi dilengkapi dengan pilihan tampilan list dan grid, foto pada halaman detail, serta penggunaan kembali fitur favorit dari Modul 6. Melalui praktikum ini, mahasiswa dapat memahami cara menampilkan data dan gambar secara lebih efisien, termasuk ketika gambar gagal dimuat atau koneksi internet tidak tersedia.

B. Tujuan Praktikum

Setelah menyelesaikan modul ini, mahasiswa mampu:

  • Mendaftarkan asset gambar dan custom font di pubspec.yaml, lalu menggunakannya dengan Image.asset dan ThemeData.
  • Menampilkan gambar dari internet dengan Image.network beserta loading state dan error state.
  • Menampilkan data dengan ListView.builder dan GridView.builder.
  • Mengganti tampilan list dan grid dengan state lokal (setState) tanpa mengganggu state favorit di Provider.

C. Alat

Perangkat dan dependensi yang digunakan selama praktikum:

  • Flutter SDK versi stable, VS Code dengan extension Flutter, dan project resepku dari Modul 6.
  • Emulator Android atau HP Android yang terhubung ke internet, karena foto resep diambil dari cdn.dummyjson.com.
  • File asset dari link berikut: logo.png, placeholder.png, dan tiga file font Poppins (Regular, Medium, Bold). Font Poppins juga dapat diunduh dari fonts.google.com; berlisensi SIL Open Font License.

D. Langkah-langkah Praktikum

Bagian A — Asset Gambar dan Custom Font

Bertujuan menambahkan logo, gambar placeholder, dan font Poppins ke ResepKu.

1. Menyiapkan folder assets

Pada direktori utama project ResepKu dibuat folder assets yang sejajar dengan folder lib. Di dalamnya dibuat subfolder images dan fonts. File logo.png serta placeholder.png disalin ke assets/images, sedangkan Poppins-Regular.ttf, Poppins-Medium.ttf, dan Poppins-Bold.ttf disalin ke assets/fonts. Nama file harus sama persis dengan yang digunakan pada konfigurasi project.

2. Mendaftarkan asset dan font di pubspec.yaml

Buka file pubspec.yaml, kemudian daftarkan folder assets/images dan keluarga font Poppins pada bagian flutter. Ketiga file font dicantumkan dengan bobot masing-masing, yaitu Regular sebagai normal (400), Medium dengan weight 500, dan Bold dengan weight 700. Indentasi YAML harus diperhatikan agar konfigurasi terbaca dengan benar. Setelah disimpan, jalankan flutter pub get apabila dependensi atau asset belum diproses secara otomatis.

3. Memasang font di tema aplikasi

Pada lib/main.dart, parameter fontFamily: 'Poppins' ditambahkan ke ThemeData agar teks aplikasi menggunakan font yang telah didaftarkan. Jika darkTheme dari Latihan 1 Modul 6 digunakan, fontFamily yang sama juga ditambahkan pada darkTheme.

4. Menambahkan logo di AppBar

Pada lib/pages/home_page.dart, title AppBar diubah menjadi Row yang berisi Image.asset('assets/images/logo.png', height: 32), SizedBox sebagai jarak, dan teks ResepKu. Setelah perubahan asset dan font selesai, aplikasi dihentikan lalu dijalankan kembali menggunakan flutter run karena asset baru dimasukkan pada proses build.

Checkpoint 1

Checkpoint 1 dilakukan dengan menampilkan halaman Home dengan logo di AppBar dan seluruh teks memakai font Poppins.

Bagian B — ListView.builder dan Foto Resep

Bertujuan menampilkan foto resep dari internet di setiap baris, lengkap dengan loading state dan error state, menggunakan ListView.builder.

1. Membuat widget RecipeImage

File baru lib/widgets/recipe_image.dart dibuat untuk menampilkan foto resep dari internet menggunakan Image.network.

Widget RecipeImage menerima URL gambar dan cacheWidth. Parameter loadingBuilder menampilkan tampilan sementara selama gambar diunduh, sedangkan errorBuilder menampilkan assets/images/placeholder.png apabila URL tidak dapat dimuat atau koneksi terputus. BoxFit.cover digunakan agar foto memenuhi area tampilan tanpa mengubah proporsinya.

2. Menambahkan thumbnail pada RecipeTile

Mengganti seluruh isi recipe_tile.dart. Perubahannya hanya pada leading: CircleAvatar diganti foto berukuran 56 × 56 dengan sudut membulat.

File lib/widgets/recipe_tile.dart diperbarui dengan mengganti CircleAvatar pada bagian leading menjadi foto resep berukuran 56 × 56 yang dibungkus ClipRRect agar sudutnya membulat. Foto ditampilkan menggunakan RecipeImage dengan cacheWidth: 168. Pengelolaan ikon favorit melalui FavoriteProvider tetap dipertahankan.

3. Menggunakan ListView.builder di HomePage

Pada lib/pages/home_page.dart, daftar resep yang sebelumnya menggunakan ListView biasa diganti dengan ListView.builder.

Parameter itemCount diisi jumlah data pada dummyRecipes, sedangkan itemBuilder membuat RecipeTile sesuai index. Logo pada AppBar dan FavoriteBadgeButton tetap dipasang. Dengan builder, item daftar dibuat ketika dibutuhkan sehingga lebih sesuai untuk menampilkan data yang jumlahnya dapat bertambah.

Jalankan aplikasi. Setiap resep kini memiliki foto. Saat aplikasi pertama dibuka, perhatikan kotak berikon yang muncul sebentar sebelum foto tampil; itulah loading state.

4. Menguji error state

Error state diuji dengan mengaktifkan mode pesawat pada emulator atau HP, kemudian menutup dan membuka kembali aplikasi.

Foto yang gagal diganti gambar placeholder, dan aplikasi tidak menampilkan error merah. Setelah itu kembalikan koneksi atau URL seperti semula.

Checkpoint 2

Checkpoint 2 dilakukan dengan menampilkan halaman Home dengan thumbnail foto resep, dan halaman Home ketika error state aktif (gambar placeholder tampil).

Bagian C — GridView dan Tombol Ganti Tampilan

Bertujuan menampilkan resep sebagai grid kartu berfoto, dan berganti antara list dan grid dengan satu tombol.

1. Membuat RecipeGridCard

File baru lib/widgets/recipe_grid_card.dart dibuat untuk menampilkan resep dalam bentuk kartu

Kartu menggunakan Card dan InkWell, kemudian menampilkan foto melalui RecipeImage. Tombol favorit diletakkan di atas foto menggunakan Stack dan Positioned, sedangkan nama resep, rating, serta waktu memasak ditampilkan pada bagian bawah kartu. Menekan kartu akan membuka halaman Detail.

2. Membuat HomePage dengan tampilan list dan grid

Mengganti seluruh isi home page untuk mendukung tampilan list dan grid

HomePage diubah menjadi StatefulWidget karena perlu menyimpan state lokal _isGrid. Nilai awal false menampilkan list. Tombol pada AppBar mengubah nilai _isGrid melalui setState(), sehingga aplikasi dapat berpindah antara _buildList() yang menggunakan ListView.builder dan _buildGrid() yang menggunakan GridView.builder. Grid menggunakan dua kolom, mainAxisSpacing dan crossAxisSpacing sebesar 8, serta childAspectRatio 3/4. FavoriteBadgeButton tetap dipertahankan

Langkah C.3 — Menghitung ukuran kartu

Pada HP dengan lebar layar 360 dp, hitung lebar dan tinggi setiap kartu grid. Gunakan rumus dari Pertemuan 10 dan tuliskan langkahnya di laporan.

Jawab: Perhitungan dilakukan berdasarkan lebar layar 360 dp, padding GridView 8 dp pada sisi kiri dan kanan, jarak antarkolom(crossAxisSpacing) 8 dp, jumlah kolom(crossAxisCount) 2, serta childAspectRatio 3/4. Lebar area grid dihitung setelah dikurangi padding kiri dan kanan. Lebar satu kartu diperoleh setelah lebar area dikurangi jarak antarkolom, kemudian dibagi dua. Tinggi kartu dihitung dari lebar kartu dibagi rasio 3/4.

Komponen Perhitungan Hasil
Lebar area grid 360 − (2 × 8) 344 dp
Lebar satu kartu (344 − 8) ÷ 2 168 dp
Tinggi satu kartu 168 ÷ (3/4) 224 dp

Dengan demikian, lebar setiap kartu adalah 168 dp dan tinggi setiap kartu adalah 224 dp. Rasio 3/4 berarti perbandingan lebar terhadap tinggi adalah 3:4, sehingga tinggi kartu lebih besar daripada lebarnya.

Pertanyaan Analisis

1. Pada skenario 3 dan 4 Langkah D.2, status favorit tetap sama walaupun tampilan berganti dari grid ke list. Padahal RecipeGridCard dan RecipeTile adalah dua widget yang berbeda. Jelaskan mengapa, dengan mengaitkannya pada Modul 6.
Status favorit tetap sama ketika tampilan berubah dari grid ke list karena data favorit disimpan di dalam FavoriteProvider, bukan pada masing-masing widget. Ketika pengguna menandai resep sebagai favorit melalui RecipeGridCard, perubahan tersebut disimpan oleh Provider dan diberitahukan kepada widget lain melalui notifyListeners(). Saat tampilan diganti menjadi list, RecipeTile tetap mengambil status favorit dari Provider yang sama menggunakan context.watch. Jadi, meskipun kedua tampilan menggunakan widget yang berbeda, data favoritnya tetap berasal dari satu tempat. Hal inilah yang membuat status favorit tidak berubah ketika pengguna berpindah tampilan.

2. Di dalam loadingBuilder terdapat baris if (loadingProgress == null) return child;. Apa yang akan tampil jika baris tersebut dihapus? Jelaskan alasannya.
Baris if (loadingProgress == null) return child; berfungsi untuk menampilkan gambar setelah proses pengunduhan selesai. Jika baris tersebut dihapus, fungsi loadingBuilder akan tetap mengembalikan tampilan sementara berupa ColoredBox yang berisi ikon restaurant_menu, meskipun gambar sebenarnya sudah berhasil dimuat. Akibatnya, foto resep tidak akan muncul karena widget yang ditampilkan selalu berupa tampilan loading. Oleh karena itu, kondisi tersebut diperlukan agar gambar dapat ditampilkan setelah proses pengunduhan selesai.

3. Hitung berapa pixel foto thumbnail yang di-decode dengan dan tanpa cacheWidth: 168, jika foto asli dari server berukuran 1200 × 800 pixel. Apa akibatnya bagi memory ketika datanya menjadi 50 resep pada Modul 8?
Dengan menggunakan cacheWidth: 168, foto asli berukuran 1200 × 800 piksel akan di-decode dengan lebar 168 piksel dan tinggi sekitar 112 piksel agar perbandingan ukurannya tetap sama. Dengan demikian, jumlah pikselnya menjadi 168 × 112 = 18.816 piksel. Sementara itu, tanpa menggunakan cacheWidth, gambar tetap di-decode pada ukuran aslinya, yaitu 1200 × 800 = 960.000 piksel. Artinya, penggunaan cacheWidth menghasilkan jumlah piksel sekitar 51 kali lebih sedikit. Apabila terdapat 50 resep dan seluruh gambarnya di-decode, totalnya secara teoritis mencapai 940.800 piksel dengan cacheWidth, sedangkan tanpa cacheWidth mencapai 48.000.000 piksel. Namun, karena menggunakan ListView.builder, item dibuat secara bertahap sesuai kebutuhan sehingga tidak semua gambar harus dimuat sekaligus. Oleh karena itu, penggunaan cacheWidth tetap membantu mengurangi penggunaan memori ketika jumlah resep semakin banyak.

4. Logo memakai Image.asset, sedangkan foto resep memakai Image.network. Mengapa logo tidak sebaiknya diambil dari internet, dan mengapa foto resep tidak dimasukkan ke asset?
Logo menggunakan Image.asset karena merupakan bagian dari identitas aplikasi yang disimpan secara lokal di dalam folder assets. Dengan demikian, logo dapat langsung ditampilkan tanpa memerlukan koneksi internet dan tetap tersedia ketika aplikasi digunakan secara offline. Sementara itu, foto resep menggunakan Image.network karena gambar tersebut diambil dari internet melalui URL yang terdapat pada data resep. Apabila seluruh foto resep dimasukkan ke dalam assets, ukuran aplikasi akan semakin besar karena semua gambar harus disertakan ke dalam file aplikasi. Dengan menggunakan Image.network, foto resep dapat diambil dari internet tanpa harus menyimpan seluruh gambar di dalam project. Selain itu, penggunaan loadingBuilder dan errorBuilder membantu aplikasi menangani proses pemuatan gambar maupun kondisi ketika gambar gagal ditampilkan.

Latihan 1 — Filter Cuisine

Menambahkan fitur penyaringan resep berdasarkan jenis masakan (cuisine). Pengguna dapat memilih kategori melalui deretan ChoiceChip yang bisa digeser ke samping. Filter harus tetap berfungsi ketika pengguna berpindah antara tampilan list dan grid.

Memodifikasi file home_page.dart

Menambahkan deretan ChoiceChip di bawah AppBar Home. Daftar cuisine diambil langsung dari data dummyRecipes agar kategori tidak perlu ditulis manual. Pilihan chip akan menyaring resep untuk mode list maupun grid. State _cuisine menggunakan nilai null untuk menunjukkan bahwa semua resep ditampilkan.

Penjelasan Kode
  • Variabel _cuisine bertipe String? untuk menyimpan kategori yang dipilih. Nilai null berarti tidak ada filter yang diterapkan.
  • map() mengambil nilai cuisine dari setiap resep, toSet() menghilangkan kategori yang duplikat, dan toList() mengubahnya menjadi List.
  • filteredRecipes berisi seluruh resep ketika _cuisine bernilai null. Jika kategori dipilih, where() mengambil resep yang cuisine-nya sama dengan pilihan pengguna.
  • ChoiceChip menampilkan pilihan Semua dan seluruh kategori yang tersedia. Perubahan pilihan dibungkus dengan setState() agar daftar diperbarui.
  • SizedBox memberikan tinggi 56 dp untuk daftar chip horizontal. Expanded membuat list atau grid mengisi sisa ruang di dalam Column.
  • _buildList() dan _buildGrid() sama-sama menerima filteredRecipes sehingga filter tetap berlaku saat tampilan berganti.

Latihan 2 - Halaman Favorit yang Lebih Rapi

Berfokus pada pengembangan halaman Favorit agar lebih interaktif. Perubahan yang diminta adalah menggunakan ListView.separated, menampilkan thumbnail foto resep, dan menerapkan Dismissible agar resep dapat dihapus dari daftar favorit dengan cara digeser ke kiri. Setelah dihapus, aplikasi menampilkan SnackBar berisi nama resep tersebut.

Memodifikasi file lib/pages/favorite_page.dart

Memperbarui halaman Favorit menggunakan ListView.separated, thumbnail RecipeImage, dan Dismissible untuk menghapus resep dengan menggeser item ke kiri. Setiap Dismissible menggunakan ValueKey(recipe.id) sebagai identitas yang unik dan stabil. Tombol Hapus Semua dari Latihan 2 Modul 6 tetap dipertahankan, termasuk AlertDialog dan kondisi tombol nonaktif ketika daftar favorit kosong.

Penjelasan Kode
  • Consumer< FavoriteProvider> memantau perubahan daftar favorit dan membangun ulang bagian halaman yang menggunakan data tersebut.
  • ListView.separated menampilkan resep secara vertikal. separatorBuilder menghasilkan Divider sebagai pemisah antaritem.
  • Dismissible memungkinkan item dihapus dengan gestur. DismissDirection.endToStart membatasi penggeseran dari kanan ke kiri, sedangkan background menampilkan latar merah dan ikon hapus pada arah tersebut.
  • ValueKey(recipe.id) memberikan identitas unik dan stabil berdasarkan ID resep, bukan posisi item dalam daftar.
  • onDismissed memanggil toggle(recipe) untuk menghapus resep dari FavoriteProvider, lalu ScaffoldMessenger menampilkan SnackBar berisi nama resep yang dihapus.
  • RecipeImage menampilkan thumbnail dari URL dan tetap memiliki loading serta error state. cacheWidth 192 digunakan untuk thumbnail 64 dp pada kepadatan layar 3×.
  • Tombol Hapus Semua tetap menggunakan AlertDialog. Method clear() hanya dipanggil apabila pengguna mengonfirmasi, sedangkan tombol nonaktif ketika favorite.count bernilai 0.

Latihan 3 - Foto yang Mengecil Saat Di-scroll

Mengubah halaman Detail menjadi CustomScrollView. Foto resep ditampilkan sebagai background FlexibleSpaceBar pada SliverAppBar dengan pinned: true dan expandedHeight: 260. Informasi dan pengaturan porsi ditempatkan pada SliverToBoxAdapter, sedangkan daftar bahan menggunakan SliverList.builder. Foto dimuat menggunakan CachedNetworkImage agar dapat disimpan dalam cache perangkat.

Untuk foto di SliverAppBar, gunakan package cached_network_image agar foto tersimpan di disk dan tidak diunduh ulang ketika aplikasi dibuka kembali: 

flutter pub add cached_network_image
Memodifikasi file lib/pages/detail_page.dart

Memperbarui embuat halaman detail resep menjadi lebih dinamis. Foto resep ditampilkan sebagai latar pada SliverAppBar dan ukurannya akan mengecil ketika pengguna melakukan scroll. Modul meminta penggunaan CustomScrollView, SliverAppBar, SliverToBoxAdapter, dan SliverList.builder. Selain itu, gambar menggunakan package cached_network_image agar dapat disimpan dalam cache dan tidak perlu selalu diunduh ulang ketika aplikasi dibuka kembali.

Penjelasan Kode
  • CustomScrollView menggabungkan beberapa komponen sliver agar foto, informasi resep, dan daftar bahan dapat digulir dalam satu halaman.
  • SliverAppBar menggunakan pinned: true agar AppBar tetap terlihat di bagian atas dan expandedHeight: 260 untuk menentukan tinggi saat terbuka.
  • FlexibleSpaceBar menempatkan CachedNetworkImage sebagai background. Gambar akan mengikuti perubahan tinggi SliverAppBar ketika halaman digulir.
  • CachedNetworkImage memuat gambar dari URL dan menyimpan hasilnya dalam cache. placeholder menampilkan indikator selama gambar dimuat, sedangkan errorWidget menampilkan asset placeholder ketika gambar gagal dimuat.
  • SliverToBoxAdapter digunakan untuk menempatkan widget biasa, yaitu informasi resep, pengaturan porsi, total kalori, dan judul Bahan ke dalam CustomScrollView.
  • SliverList.builder menampilkan bahan resep sesuai jumlah ingredients dan membangun item saat dibutuhkan.
  • State jumlah porsi tetap menggunakan setState(), sedangkan status favorit tetap dibaca dan diubah melalui FavoriteProvider.

E. Kesimpulan

Berdasarkan praktikum yang telah dilakukan, dapat disimpulkan bahwa penggunaan list, grid, gambar, dan asset merupakan bagian penting dalam membangun aplikasi Flutter yang lebih informatif dan nyaman digunakan. Melalui praktikum ini, aplikasi ResepKu dikembangkan dengan menambahkan asset lokal berupa logo dan custom font Poppins, serta menampilkan foto resep dari internet menggunakan Image.network yang dilengkapi loading state dan error state. Penggunaan ListView.builder dan GridView.builder juga memberikan pemahaman mengenai cara menampilkan data dalam susunan yang berbeda secara efisien, sedangkan setState() digunakan untuk mengatur perpindahan tampilan dari list ke grid. Selain itu, penggunaan RecipeImage memungkinkan komponen gambar digunakan kembali pada daftar resep, tampilan grid, dan halaman detail, sementara Provider dari Modul 6 menjaga agar status favorit tetap konsisten meskipun tampilan berubah.
Pada bagian latihan, fitur filter cuisine memudahkan pengguna mencari resep berdasarkan jenis masakan, halaman Favorit menjadi lebih interaktif melalui thumbnail dan Dismissible, serta penggunaan CustomScrollView, SliverAppBar, dan CachedNetworkImage memberikan pengalaman tampilan detail yang lebih dinamis. Dengan demikian, praktikum ini membantu memahami cara menggabungkan pengelolaan data, gambar, asset, dan komponen scrollable sehingga aplikasi dapat dikembangkan dengan struktur yang lebih rapi dan pengalaman pengguna yang lebih baik.
