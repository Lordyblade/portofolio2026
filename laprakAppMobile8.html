Laporan Praktikum 8 - Aplikasi Mobile

HTTP Request dan Integrasi API pada ResepKu

Ibrahim Mousa Dhani 2411532010
IF - Universitas Andalas

A. Pendahuluan

HTTP Request dan integrasi API merupakan salah satu bagian penting dalam pengembangan aplikasi mobile karena memungkinkan aplikasi berkomunikasi dengan server untuk mengambil maupun mengirim data. Dalam Flutter, proses komunikasi tersebut dapat dilakukan menggunakan REST API dengan beberapa metode HTTP, seperti GET untuk mengambil data dan POST untuk mengirim data. Data yang diterima dari server umumnya berbentuk JSON, sehingga perlu diubah menjadi objek menggunakan proses parsing seperti factory fromJson. Selain itu, Flutter menyediakan fitur asynchronous seperti Future dan async/await untuk menjalankan proses yang membutuhkan waktu tanpa menghambat aplikasi, serta FutureBuilder untuk menampilkan kondisi loading, data, dan error berdasarkan hasil proses tersebut.

Pada praktikum ini, aplikasi ResepKu dikembangkan lebih lanjut dengan dengan mengganti sumber data yang sebelumnya menggunakan enam resep dummy menjadi data yang diambil langsung dari REST API DummyJSON. Proses pengambilan data dilakukan menggunakan package http melalui class RecipeService, kemudian respons JSON diubah menjadi objek Recipe dan ditampilkan menggunakan FutureBuilder. Praktikum ini juga menambahkan penanganan kondisi ketika data sedang dimuat atau gagal diperoleh, tombol untuk mencoba kembali, serta fitur pull-to-refresh. Selain itu, dibuat fitur penambahan resep melalui form menggunakan metode POST untuk mengirim data ke server. Melalui praktikum ini, aplikasi ResepKu dapat menampilkan data secara lebih dinamis sekaligus memberikan pemahaman mengenai penerapan komunikasi API dalam aplikasi Flutter.

B. Tujuan Praktikum

Setelah menyelesaikan modul ini, mahasiswa mampu:

  • Membaca struktur respons JSON dari REST API dan membuat factory fromJson untuk model Recipe.
  • Melakukan request GET dengan package http di dalam sebuah class service.
  • Menampilkan data dengan FutureBuilder lengkap dengan loading state, error state, tombol coba lagi, dan pull-to-refresh.
  • Mengirim data baru dengan request POST dari sebuah form, lalu menangani hasilnya.

C. Alat

Perangkat dan dependensi yang digunakan selama praktikum:

  • Flutter SDK versi stable, VS Code dengan extension Flutter, dan project resepku dari Modul 6.
  • Emulator Android atau HP Android yang terhubung ke internet, karena foto resep diambil dari cdn.dummyjson.com.
  • Browser di laptop untuk membaca respons API dan dokumentasi https://dummyjson.com/docs/recipes.
  • Package http dari pub.dev (dipasang pada Langkah A.2).

D. Langkah-langkah Praktikum

Bagian A — Mengenal API dan Model fromJson

Bertujuan memahami bentuk data dari server, lalu menyiapkan model Recipe agar dapat dibuat dari JSON.

1. Membaca respons API di browser

Buka URL berikut di browser laptop: 

https://dummyjson.com/docs/recipes
Pertanyaan Jawaban
Nilai total 50 resep
Key yang berisi daftar resep recipes
Tipe nilai rating pada resep pertama (int atau double?) double(nilai desimal 4.6 pada respons JSON)
Tiga key resep yang belum ada di model Recipe Modul 7 instructions, tags, dan reviewCount
2. Memasang package http

Jalankan perintah berikut di terminal:

flutter pub add http

Package ini digunakan untuk mengirim request HTTP ke server dan menerima responsnya. Setelah proses pemasangan berhasil, dependency http tercatat pada pubspec.yaml dan dapat diimpor pada file service.

3. Model Recipe dengan fromJson

File lib/models/recipe.dart diperbarui dengan menambahkan field instructions dan factory constructor Recipe.fromJson

. Factory tersebut mengambil nilai dari setiap key JSON sesuai tipe data yang dibutuhkan model. Field yang bersifat opsional diberi nilai bawaan agar aplikasi tidak mengalami error ketika respons server tidak menyertakan field tertentu. Nilai rating dibaca sebagai num lalu dikonversi menjadi double, sedangkan array ingredients dan instructions dikonversi menjadi List< String >.

4. Menghapus data dummy

Setelah model dapat membaca JSON, file lib/data/dummy_recipes.dart beserta folder data dihapus karena sumber resep selanjutnya berasal dari API.

Penghapusan ini menyebabkan referensi dummyRecipes pada HomePage sementara menampilkan error sampai bagian B selesai. Jika filter cuisine dari Modul 7 sudah digunakan, daftar cuisine perlu diambil dari data recipes yang diterima melalui FutureBuilder, bukan lagi dari dummyRecipes.

Bagian B — RecipeService dan FutureBuilder

Bertujuan mengambil 50 resep dari server dengan GET, lalu menampilkannya dengan FutureBuilder lengkap dengan loading dan error state.

1. Membuat RecipeService

Membuat folder baru yaitu lib/services, kemudian file recipe_service.dart ditambahkan.

Class RecipeService menjadi tempat seluruh komunikasi dengan API, termasuk request GET ke endpoint /recipes?limit=50. Respons diperiksa status kodenya, di-decode menjadi Map JSON, lalu daftar pada key recipes diubah menjadi List melalui Recipe.fromJson. Request juga diberi batas waktu 10 detik agar aplikasi tidak menunggu tanpa batas.

2. Mendaftarkan RecipeService sebagai Provider

Ganti seluruh isi lib/main.dart.

RecipeService didaftarkan pada MultiProvider di lib/main.dart menggunakan Provider biasa, bukan ChangeNotifierProvider, karena service tidak menyimpan state yang berubah dan tidak membutuhkan notifyListeners. FavoriteProvider dan ThemeProvider tetap dipertahankan agar fitur favorit dan tema dari Modul 6 tidak hilang. Provider juga mengatur pemanggilan service.close() ketika service tidak lagi digunakan. Setelah mengubah main.dart, aplikasi perlu di-hot restart.

3. Widget ErrorView

Buat widget untuk error state agar dapat dipakai di beberapa halaman

File lib/widgets/error_view.dart dibuat sebagai widget khusus untuk menampilkan kondisi ketika request gagal. ErrorView menampilkan ikon koneksi bermasalah, pesan error, dan tombol Coba lagi. Tombol tersebut menerima callback onRetry sehingga dapat digunakan kembali oleh halaman yang membutuhkan penanganan error.

4. HomePage dengan FutureBuilder

Ganti seluruh isi lib/pages/home_page.dart.

HomePage diperbarui agar mengambil data dari RecipeService. Future daftar resep disimpan pada field _recipesFuture dan dibuat satu kali di initState, sehingga perubahan tampilan list atau grid tidak mengirim request baru. FutureBuilder kemudian memeriksa connectionState, hasError, dan data untuk menampilkan loading indicator, ErrorView, atau daftar resep. Fungsi _reload digunakan untuk mencoba request kembali, sedangkan RefreshIndicator menyediakan fitur pull-to-refresh. Fungsi _buildList dan _buildGrid menerima data resep sebagai parameter agar keduanya memakai hasil API yang sama.

5. Menampilkan langkah memasak di halaman detail

Model Recipe yang berasal dari API sudah memiliki data instructions. Pada halaman detail, daftar langkah memasak ditambahkan setelah daftar bahan. Setiap langkah ditampilkan menggunakan ListTile dengan nomor urut. Jika halaman detail menggunakan ListView, widget Text dan ListTile dapat diletakkan langsung dalam daftar children. Jika menggunakan CustomScrollView dari bonus Modul 7, judul dibungkus dengan SliverToBoxAdapter dan daftar instruksi menggunakan SliverList.builder agar tetap sesuai dengan struktur sliver.

Checkpoint 1

Checkpoint 1 dilakukan dengan menampilkan Indikator loading, Home dengan resep dari server (perlihatkan resep yang tidak ada di 6 resep dummy), dan halaman Detail yang menampilkan bagian Langkah.

6. Menguji error state dan refresh

Error state diuji dengan mengaktifkan mode pesawat lalu melakukan hot restart. Ketika request tidak dapat dilakukan, aplikasi menampilkan ErrorView beserta tombol Coba lagi. Setelah mode pesawat dimatikan, tombol tersebut digunakan untuk mengirim request ulang. Fitur pull-to-refresh kemudian diuji dengan menarik daftar resep ke bawah. Selama refresh berlangsung, daftar lama tetap terlihat dan indikator refresh muncul di bagian atas.

Checkpoint 2

Checkpoint 2 dilakukan dengan menampilkan ErrorView saat mode pesawat aktif, dan pull-to-refresh yang sedang berjalan.

Pertanyaan Analisis

1. Pada skenario 2, setiap refresh membuat objek Recipe yang baru dari JSON. Mengapa status favorit tetap benar? Hubungkan dengan cara FavoriteProvider membandingkan resep (Modul 6).
Karena FavoriteProvider membandingkan resep berdasarkan nilai id, bukan berdasarkan objek Recipe secara langsung. Setiap kali data dimuat ulang, aplikasi memang membuat objek Recipe baru dari JSON, tetapi resep tersebut tetap memiliki ID yang sama dengan data sebelumnya. Method isFavorite() pada FavoriteProvider memeriksa kesamaan ID tersebut, sehingga status favorit tetap dapat dikenali meskipun objeknya berbeda. Dengan cara ini, daftar favorit tidak bergantung pada alamat objek di memori, melainkan pada identitas resep.

2. Pada skenario 3, mengapa menekan tombol grid tidak memunculkan indikator loading? Apa yang akan terjadi jika future ditulis langsung di dalam build()?
Karena Future daftar resep sudah dibuat satu kali di initState() dan disimpan dalam variabel _recipesFuture. Ketika tombol grid ditekan, setState() hanya mengubah tampilan dari list menjadi grid atau sebaliknya, sedangkan Future yang digunakan FutureBuilder tetap sama. Jika pemanggilan fetchRecipes() ditulis langsung di dalam build(), setiap build dijalankan request baru akan dibuat. Akibatnya, perpindahan tampilan dapat mengirim request berulang dan indikator loading muncul kembali.

3. HomePage tidak memanggil http.get secara langsung, melainkan melalui RecipeService. Sebutkan dua keuntungan cara ini
Kode lebih terstruktur karena bagian tampilan tidak perlu mengurus proses komunikasi dengan server secara langsung, logika request dapat digunakan kembali oleh beberapa halaman tanpa harus menulis kode HTTP berulang kali, dan proses pengujian juga menjadi lebih mudah karena client pada RecipeService dapat diganti dengan MockClient, sehingga request dapat diuji menggunakan respons palsu tanpa membutuhkan koneksi internet.

4. Setelah POST berhasil, server memberi id baru, tetapi resep tidak muncul saat daftar dimuat ulang. Jelaskan penyebabnya, dan bagaimana aplikasi dengan server sungguhan biasanya menampilkan data yang baru ditambahkan.
Resep yang dikirim melalui POST tidak muncul kembali setelah daftar dimuat ulang karena DummyJSON hanya menyimulasikan proses penambahan data. Server mengembalikan respons yang berisi data resep dan ID baru, tetapi data tersebut tidak benar-benar disimpan pada server. Pada aplikasi yang menggunakan server sungguhan, data biasanya disimpan ke database setelah request berhasil. Ketika daftar resep dimuat ulang, request GET akan mengambil data terbaru dari database sehingga resep yang baru ditambahkan dapat muncul. Aplikasi juga dapat memperbarui daftar lokal berdasarkan respons POST yang diterima.

5. Di AddRecipePage terdapat if (!mounted) return; setelah await. Jelaskan skenario yang dicegah oleh baris tersebut.
Pemeriksaan if (!mounted) return; digunakan untuk memastikan halaman masih aktif sebelum aplikasi melanjutkan proses setelah menjalankan operasi asynchronous. Contohnya, ketika pengguna menekan Simpan lalu menutup halaman form sebelum request POST selesai, halaman tersebut sudah tidak lagi terpasang pada widget tree. Tanpa pemeriksaan mounted, aplikasi masih dapat mencoba menggunakan context atau menjalankan navigasi pada halaman yang sudah ditutup. Kondisi ini dapat menimbulkan error, sehingga pemeriksaan mounted diperlukan agar proses hanya dilanjutkan ketika halaman masih aktif.

Latihan 1 — Pencarian Resep

Menambahkan halaman pencarian yang dibuka dari ikon kaca pembesar di AppBar Home. User mengetik kata kunci, menekan Enter, lalu hasil ditampilkan dengan FutureBuilder.

Menambahkan method searchRecipes()

Buka file lib/services/recipe_service.dart. Pada file ini, sebelumnya sudah terdapat method fetchRecipes() untuk mengambil seluruh resep dari server. Lalu tambahkan method searchRecipes() tepat setelah method fetchRecipes() dan sebelum method _checkStatus()

Method searchRecipes() digunakan untuk melakukan pencarian resep berdasarkan kata kunci yang diberikan pengguna. Parameter query berisi teks pencarian, kemudian Uri.parse() digunakan untuk membentuk alamat endpoint pencarian.

Bagian .replace(queryParameters: {'q': query}) digunakan agar kata kunci dimasukkan ke parameter URL dengan format encoding yang benar, termasuk apabila terdapat spasi atau karakter khusus. Selanjutnya, _client.get() mengirimkan request GET ke server. Respons yang diterima diubah dari JSON menjadi objek Recipe menggunakan Recipe.fromJson(). Dengan demikian, method ini dapat mengembalikan daftar resep sesuai kata kunci yang dicari.

Membuat SearchPage

Buat file baru yaitu lib/pages/search_page.dart. Halaman ini merupakan halaman khusus untuk pencarian resep. Berbeda dengan HomePage, halaman ini menggunakan FutureBuilder yang awalnya belum memiliki Future sampai pengguna memasukkan kata kunci pencarian.

Variabel _searchFuture digunakan untuk menyimpan proses pencarian resep dari server. Tipe datanya dibuat nullable karena sebelum pengguna melakukan pencarian, belum ada request yang dijalankan. Sementara itu, _query menyimpan kata kunci terakhir yang digunakan sehingga pencarian dapat dilakukan kembali apabila terjadi kesalahan.

Method _search() dipanggil ketika pengguna menekan Enter pada TextField. Fungsi trim() digunakan untuk menghilangkan spasi yang tidak diperlukan pada awal dan akhir kata kunci. Apabila input kosong, pencarian tidak dijalankan. Jika input tersedia, aplikasi membuat Future baru melalui RecipeService dan memperbarui tampilan menggunakan setState().

Method _retry() digunakan apabila request pencarian mengalami kegagalan. Method ini menjalankan kembali pencarian menggunakan kata kunci terakhir yang disimpan dalam _query.

TextField ditempatkan pada bagian title AppBar sehingga pengguna dapat langsung mengetikkan kata kunci setelah halaman pencarian dibuka. Parameter textInputAction mengatur tombol keyboard menjadi tombol pencarian, sedangkan onSubmitted menjalankan method _search() ketika pengguna menekan Enter.

FutureBuilder< List< Recipe>> digunakan untuk mengamati proses pencarian. Apabila request masih berlangsung, aplikasi menampilkan indikator loading. Jika terjadi kesalahan, aplikasi menggunakan kembali ErrorView. Apabila server tidak menemukan resep yang sesuai, aplikasi menampilkan pesan khusus. Jika data berhasil diperoleh, hasilnya ditampilkan menggunakan ListView.builder dan widget RecipeTile.

Menambahkan tombol/ikon pencarian pada HomePage

Ikon pencarian ditambahkan ke actions pada AppBar HomePage. Ketika ditekan, aplikasi membuka SearchPage menggunakan Navigator.push. Letakkan tombol ini bersama tombol tampilan grid, Favorit, dan Pengaturan yang sudah ada.

Buka file lib/pages/home_page.dart, dan tambahkan import berikut pada bagian import paling atas:

Selanjutnya, cari bagian AppBar pada method build(). Pada parameter actions, tambahkan IconButton untuk pencarian.

IconButton digunakan untuk menampilkan ikon kaca pembesar pada AppBar Home. Ketika ditekan, Navigator.push() digunakan untuk membuka halaman SearchPage. Dengan demikian, pengguna dapat melakukan pencarian resep tanpa mengubah halaman utama.

Latihan 2 - Mengubah dan menghapus resep

Menambahkan PopupMenuButton di AppBar halaman detail

Menambahkan method updateRecipe() dan deleteRecipe()

Buka file lib/services/recipe_service.dart, dan tambahkan dua method baru di dalam class RecipeService, tepat setelah method addRecipe() dan sebelum _checkStatus().

Method updateRecipe() digunakan untuk mengubah nama resep berdasarkan ID yang dimiliki. Parameter id menentukan resep yang akan diubah, sedangkan name berisi nama baru yang dikirimkan oleh pengguna.

Method deleteRecipe() digunakan untuk menghapus resep berdasarkan ID. Proses penghapusan menggunakan metode HTTP DELETE. Alamat endpoint disusun menggunakan ID resep yang akan dihapus. Setelah server memberikan respons, aplikasi memeriksa status request dan mengubah respons JSON menjadi Map. Respons tersebut nantinya digunakan untuk memeriksa nilai isDeleted. Apabila bernilai true, aplikasi akan menampilkan pesan bahwa resep berhasil dihapus.

Menambahkan PopupMenuButton pada halaman Detail

Buka file lib/pages/detail_page.dart. Pada file ini, kita akan melakukan tiga perubahan, yaitu menambahkan import RecipeService, membuat method untuk mengubah dan menghapus resep, serta menambahkan PopupMenuButton di bagian SliverAppBar.

a. Menambahkan import RecipeService di bagian paling atas file. Import ini diperlukan agar halaman Detail dapat memanggil method PUT dan DELETE melalui Provider.

b. Membuat method untuk mengubah nama resep. Letakkan method berikut di dalam class _DetailPageState, setelah method _removeServing() dan sebelum @override Widget build().

Method _editRecipeName() digunakan untuk menampilkan dialog yang berisi TextField agar pengguna dapat memasukkan nama resep baru.

TextEditingController digunakan untuk mengambil dan mengelola teks yang dimasukkan. Nilai awal controller diisi menggunakan widget.recipe.name, sehingga nama resep saat ini sudah muncul di dalam kolom input.

Ketika tombol Simpan ditekan, aplikasi mengambil teks baru dan mengirimkannya melalui method updateRecipe() yang terdapat di RecipeService. Jika request berhasil, nama yang dikembalikan oleh server ditampilkan melalui SnackBar. Apabila terjadi kesalahan, aplikasi menampilkan pesan kegagalan.

Bagian if (!mounted) digunakan untuk memastikan halaman Detail masih aktif sebelum menggunakan BuildContext setelah proses asynchronous selesai.

c. Membuat method untuk menghapus resep. Masih di dalam class _DetailPageState, letakkan method _confirmDeleteRecipe() berikut setelah _editRecipeName() dan sebelum method build().

Method _confirmDeleteRecipe() digunakan untuk menampilkan dialog konfirmasi sebelum resep dihapus. Pengguna diberikan dua pilihan, yaitu Batal dan Hapus. Jika memilih Batal, proses penghapusan tidak dijalankan.

Namun, apabila pengguna memilih Hapus, aplikasi memanggil method deleteRecipe() dari RecipeService dengan menyertakan ID resep yang sedang dibuka.

Setelah server memberikan respons, aplikasi memeriksa apakah isDeleted bernilai true. Jika berhasil, SnackBar ditampilkan dan halaman Detail ditutup menggunakan Navigator.pop(context). Jika terjadi kesalahan, aplikasi menampilkan pesan bahwa proses penghapusan gagal.

d. Menambahkan PopupMenuButton pada SliverAppBar. Pada bagian SliverAppBar di dalam method build(), bagian actions biasanya hanya berisi tombol favorit. Tambahkan PopupMenuButton setelah tombol favorit seperti gambar berikut.

PopupMenuButton< String> digunakan untuk menampilkan menu pilihan ketika ikon tiga titik ditekan. Menu tersebut memiliki dua pilihan, yaitu Ubah nama dan Hapus resep.

Parameter onSelected digunakan untuk menentukan tindakan berdasarkan pilihan pengguna. Apabila memilih Ubah nama, aplikasi memanggil _editRecipeName(). Sementara itu, apabila memilih Hapus resep, aplikasi menjalankan _confirmDeleteRecipe().

Dengan penambahan ini, pengguna dapat melakukan perubahan maupun penghapusan resep langsung dari halaman Detail.

Latihan 3 - Unit test tanpa internet

Menguji fungsi Recipe.fromJson() dan RecipeService.fetchRecipes() tanpa harus mengakses internet atau server DummyJSON secara langsung.

Membuat file pengujian recipe_service_test.dart pada folder test

Pengujian pertama memastikan rating bernilai int pada JSON dapat dikonversi menjadi double serta field yang tidak tersedia memperoleh nilai bawaan. Pengujian berikutnya memastikan fetchRecipes dapat membaca respons palsu dan melempar RecipeServiceException ketika server memberikan status 404

Kode diawali dengan beberapa import yang diperlukan untuk menjalankan pengujian. Package dart:convert digunakan untuk mengubah data berbentuk Map menjadi JSON menggunakan jsonEncode(). Selanjutnya, flutter_test menyediakan fungsi pengujian seperti group(), test(), dan expect(). Package http digunakan untuk membuat respons HTTP, sedangkan MockClient dari http/testing.dart digunakan untuk menggantikan komunikasi dengan server asli. Selain itu, file recipe.dart dan recipe_service.dart diimpor karena keduanya merupakan bagian yang akan diuji.

Bagian pertama menggunakan group('Recipe.fromJson') untuk menguji proses konversi data JSON menjadi objek Recipe. Data pengujian dibuat dengan memasukkan id, name, dan rating yang bernilai 5 dalam bentuk integer. Setelah data diproses menggunakan Recipe.fromJson(), fungsi expect() digunakan untuk memastikan bahwa nilai rating berhasil dikonversi menjadi double dengan nilai 5.0. Pengujian juga dilakukan terhadap beberapa field yang tidak tersedia pada JSON untuk memastikan bahwa masing-masing field menggunakan nilai bawaan sesuai implementasi pada model Recipe.

Bagian kedua menggunakan group('RecipeService.fetchRecipes') untuk menguji proses pengambilan data resep menggunakan respons server palsu. MockClient dibuat untuk memberikan respons JSON yang berisi satu data resep dengan status HTTP 200. Ketika fetchRecipes() dijalankan, aplikasi akan memproses respons tersebut menjadi daftar objek Recipe. Selanjutnya, beberapa fungsi expect() digunakan untuk memastikan bahwa hasilnya berbentuk List< Recipe>, memiliki satu data, serta mempunyai nama dan rating yang sesuai dengan respons yang diberikan.

Bagian ketiga menguji penanganan kesalahan ketika server memberikan status HTTP 404. Pada pengujian ini, MockClient diatur agar mengembalikan respons dengan status 404 dan pesan Not Found. Ketika fetchRecipes() dijalankan, method _checkStatus() pada RecipeService akan memeriksa status respons tersebut dan melempar RecipeServiceException karena statusnya tidak termasuk dalam rentang 2xx. Fungsi expectLater() kemudian digunakan untuk memastikan bahwa exception yang dihasilkan sesuai dengan tipe yang diharapkan.

Dengan adanya ketiga pengujian tersebut, proses konversi data, pengambilan daftar resep, dan penanganan respons error dapat diperiksa tanpa harus mengakses server DummyJSON. Penggunaan MockClient juga membuat pengujian lebih mudah dilakukan karena respons yang diterima sudah ditentukan di dalam kode.

Pengujian

Setelah kode selesai dimasukkan dan disimpan, buka terminal VS Code pada direktori utama project ResepKu. Jalankan perintah berikut untuk menjalankan seluruh pengujian pada file yang telah dibuat.

flutter test test/recipe_service_test.dart

atau perintah ini agar menampilkan nama setiap pengujian secara lebih terperinci.

flutter test test/recipe_service_test.dart --reporter expanded

Perintah tersebut akan menjalankan tiga skenario pengujian yang sudah didefinisikan, yaitu:

1. Pengujian Recipe.fromJson untuk memastikan rating integer dapat dikonversi menjadi double dan field yang tidak tersedia menggunakan nilai bawaan.

2. Pengujian RecipeService.fetchRecipes untuk memastikan data resep berhasil diperoleh dari respons palsu dengan status 200.

3. Pengujian RecipeService.fetchRecipes untuk memastikan respons dengan status 404 menghasilkan RecipeServiceException.

Output

Jika seluruh pengujian berhasil, maka output yang ditampilkan di terminal akan menunjukkan bahwa semua test telah lulus tanpa error.

E. Kesimpulan

Berdasarkan praktikum yang telah dilakukan, dapat disimpulkan bahwa integrasi REST API memungkinkan aplikasi ResepKu mengambil dan mengirim data melalui komunikasi dengan server. Melalui penggunaan package http, RecipeService, dan factory fromJson, proses pengambilan data dapat dipisahkan dari tampilan aplikasi sehingga struktur kode menjadi lebih teratur dan mudah digunakan kembali. Penerapan FutureBuilder juga membantu aplikasi menangani beberapa kondisi request, mulai dari proses loading, data berhasil diterima, hingga error yang dapat dicoba kembali. Selain itu, penggunaan POST menunjukkan bagaimana data dari form dikirim ke server dan responsnya ditampilkan kepada pengguna, meskipun pada DummyJSON proses penambahan, perubahan, dan penghapusan hanya disimulasikan. Melalui latihan pencarian, pengubahan dan penghapusan resep, serta unit test menggunakan MockClient, pemahaman mengenai penggunaan endpoint API dan pengujian tanpa koneksi internet menjadi lebih baik. Secara keseluruhan, praktikum ini memberikan pengalaman dalam menghubungkan aplikasi Flutter dengan REST API sekaligus mempertahankan fitur yang telah dikembangkan pada modul sebelumnya.
